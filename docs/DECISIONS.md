# Decisions

A short log of technical decisions: what we chose, why, and when. Newest at the bottom.

| Date | Decision | Why |
|---|---|---|
| 2026-11-11 | **Phaser 4** for the client, code-first (not an editor-based engine) | It's a TypeScript framework you call from code, so it fits a .NET/Angular workflow. v4 is the current major version, and starting on v3 would mean migrating later. |
| 2026-11-11 | **Server is the referee.** All rules live in pure C# (`Tactics.Core`). | One source of truth, no client-side cheating, and the same inputs always give the same outputs. That makes replays and tests possible. |
| 2026-11-11 | **.NET 10 LTS** rather than .NET 11 | Both are supported until November 2028 (STS releases now get 24 months). The ecosystem is still catching up with 11: Npgsql's EF Core 11 provider is a release candidate. |
| 2026-11-11 | **Aspire** for local orchestration | One command starts the API and the client. The dashboard shows logs and traces, and URLs are injected, not hard-coded. It replaces docker-compose plus manual ports. |
| 2026-11-11 | **PostgreSQL** for persistence (from Step 12) | Free, open source, and has a first-class EF Core provider (Npgsql). It runs as a container in Aspire and Testcontainers. Same major version everywhere. |
| 2026-11-11 | Solution file is **`Tactics.slnx`** | The XML format is the .NET 10 default. It's short, readable and gives clean diffs. |
| 2026-11-11 | **`TreatWarningsAsErrors` on every project**, tests included, plus `EnforceCodeStyleInBuild` | The build check requires 0 warnings anyway. xUnit's analyzers catch real test mistakes, such as a missing cancellation token. |
| 2026-11-11 | AppHost health-checks the API on its **`http` endpoint** | With an untrusted HTTPS dev certificate (fresh machine, CI), the https probe failed. The API stayed "Unhealthy" and `WaitFor` blocked the client forever. |
| 2026-11-11 | The Vite proxy prefers **`API_HTTP`** over `API_HTTPS` | The browser → Vite → API hop stays on localhost, so plain http avoids dev-certificate problems. `secure: false` covers the https fallback. |
| 2026-11-11 | **TypeScript 7** (native compiler), with `strict: true` written explicitly | It's what create-vite 9 scaffolds. Writing `strict` explicitly documents the rule from `CLAUDE.md`, whatever the compiler's default. |
| 2026-11-11 | Vite `chunkSizeWarningLimit: 1500` | Phaser alone is ~1.4 MB minified (~360 kB gzipped). The limit sits just above it, so growth in our own code still warns. Splitting Phaser into its own cached chunk can wait for deploy polish. |
| 2026-11-11 | Tab title set at runtime (`document.title = GAME_TITLE`); `<title>` in `index.html` stays empty | It keeps the title in exactly one place in code. Trade-off: static HTML (link previews) sees no title. Revisit at Step 14. |
| 2026-11-11 | Network code lives outside Phaser (`client/src/net/`), with an injectable `fetch` | Vitest can test it without a canvas or a real server, much like constructor injection in .NET. |
| 2026-11-11 | Core namespaces follow folders: `Tactics.Core.Model`, `.Content`, `.Serialization`; `GameEngine` sits at the root | Conventional .NET layout. Later steps add rule folders next to them without one flat namespace growing forever. |
| 2026-11-11 | Content is parsed into **file DTOs** (nullable fields, enums as strings), then mapped to domain records | A missing field becomes "is missing", not a silent 0. A typo in `owner` gets a clear message instead of a parser exception. Same idea as model binding plus validation in ASP.NET. |
| 2026-11-11 | `ContentLoader` reports **every** problem at once, each as a `ContentError` with a stable **code** and a message | You fix all mistakes in one pass. Tests check codes, so messages can improve without breaking tests. This mirrors the rule-violation codes coming in Step 2. |
| 2026-11-11 | Stat minimums: `maxHp`, `power`, `move`, `minRange`, `maxRange` at least 1; `defense` at least 0; each side needs at least one unit | The plan's own Mage has defense 0. A side with no units would start an already-won game. |
| 2026-11-11 | Unknown JSON properties in content are ignored; enum names are case-insensitive | You can add your own notes fields. A typo in a required field still shows up as "missing". |
| 2026-11-11 | Rule tests use fixed stats (`AsciiBoard.DefaultUnitTypes`); real-content tests check validity only | Balancing `content/units.json` never breaks a test, but a broken file always does. Verified by rebalancing a copy: 69/69 still passed. |
| 2026-11-11 | `TacticsJson` sets `TypeInfoResolver` explicitly instead of relying on the host's default | .NET 10 single-file apps (and Native AOT) switch reflection-based JSON off by default, and the options crashed there. Core shouldn't depend on its host's settings. |
| 2026-11-11 | Core removes the `System.IO` and `System.Net.Http` implicit usings | It's a visible reminder that Core does no I/O. Reading files belongs to the tests and the API. |
| 2026-11-11 | **`ActionOutcome`**, not the plan's `ActionResult` | `ActionResult` is also an ASP.NET Core MVC type. An API file that imports both namespaces gets CS0104 "ambiguous reference", and readers would take it for the MVC type. |
| 2026-11-11 | `ActionOutcome` is a **closed hierarchy**: a private constructor and two nested records, `Accepted` and `Rejected` | An action has exactly two outcomes, and no other code can add a third. C# 14 can't prove the list is complete, so a `switch` on it still needs a `_` arm. |
| 2026-11-11 | `TacticsJson` sets **`AllowOutOfOrderMetadataProperties = true`** | System.Text.Json otherwise reads `"type"` only as the first property. PostgreSQL `jsonb` reorders keys (shortest first), so a stored move would fail to load in Step 12. The cost is extra buffering, only when `type` isn't first. |
| 2026-11-11 | New Core folders `Actions/`, `Events/`, `Rules/`, with **one file per family** (`GameAction.cs` holds every action type). `ActionOutcome` and `RuleViolation` sit at the root, next to `GameEngine`. | Namespaces keep following folders. One file per family shows every case and its `[JsonDerivedType]` line together, like a TypeScript union type. The root holds the engine's contract: what you call and what you get back. |
| 2026-11-11 | `GameEngine` is a **`partial` class**, with one file per action's rules (`GameEngine.Move.cs`; Act and Turn follow in Steps 3–4) | One entry point to call, without one huge file. Shared helpers (`Reject`, `Describe`, `Tiles`) stay in `GameEngine.cs`. |
| 2026-11-11 | `Pathfinding.Reachable` is **geometry only**: it ignores the turn, `HasMoved` and `HasActed` | Who may move is the engine's rule. Step 4's available actions reuse the same search. |
| 2026-11-11 | `ReachMap` is a **class**, not a record | It hides its came-from table behind `CanReach` and `PathTo`. A record's equality would compare that table by reference anyway. |
| 2026-11-11 | **`AlreadyActed` is checked before `AlreadyMoved`** | From Step 3, acting sets both flags. Then "already acted" is the real reason the unit can't move, and Step 3's tests expect that code. |
| 2026-11-11 | Core JSON keeps System.Text.Json's **default property order**, so `player` comes last: `{"type":"move","unitId":…,"to":…,"player":"one"}` | It writes a subtype's own properties before inherited ones. Readers match properties by name, so an ordering attribute would only be cosmetic. |
| 2026-11-11 | Board-picture tests compare with **`ignoreLineEndingDifferences: true`** | With `core.autocrlf=true`, a Windows checkout turns the line endings of a test's raw string into `\r\n`, while `AsciiBoard.Draw` writes `\n`. |
